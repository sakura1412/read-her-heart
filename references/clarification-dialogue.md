# 问答式澄清与续接

这是一种跨阶段的交互方式，不新增评估门槛或固定阶段。先检查当前用户已提供的材料、上下文及可核验记录；只在答案会改变**需求范围/执行模式、项目形态、关键方案、权限边界、验收预期或下一步判断**，且不能作有边界的假设时提问。细枝末节直接标为假设或待确认，不把每个未知项都变成问卷；优先一次问最关键的一题，必要时再问下一题，已回答的不重复问。另有一项交付偏好：到达 PRD 生成入口且用户未选类型时，按 [10](10-prd-generation.md#prd-类型由用户选择)明确询问，不能用假设替用户选择。

## 提问形式

- 用一句话交代歧义和其影响，再给**两个简短、含义不同的建议选项**。选项是帮助用户表达，不是穷举；不得为了凑二选一而误写需求。让用户始终能选择“其他”并自由输入真实情形。若根本没有两个合理选项，直接用开放式问题，不制造伪选项。
- 宿主支持带建议选项且允许自由输入的结构化提问工具时优先使用；若宿主自动提供“其他”输入框，不在选项中重复添加“其他”。若宿主不支持自由输入或没有结构化提问 UI，回退为普通消息：`① …… ② …… 其他：请直接输入您的情况`。**Skill 的文字不能自行创建原生按钮或输入框**，应以实际宿主能力为准。
- 如工具预选了首项，也必须等用户主动提交；预选、已读、沉默都不算回答。系统访问或写操作授权、公开资料扫描范围、系统登录、密码、验证码及法务/安全审批仍按各自要求确认，不以普通选项题或预选项代替。

例如项目形态不明时，只问：`这是改造已有系统，还是从 0 到 1 新建？` 建议选项为 `改造已有系统`、`从 0 到 1 新建`；“新建并对接旧系统”等由“其他”输入承接。不要因此要求提供一个不存在的系统地址或在聊天中提交账号密码。

PRD 类型题要在问题文字中说明**简版、标准版、完整版**及简短差异，快捷项仍可提供其中两个，并明确另一类可通过“其他”输入；无 UI 时直接列三类供文字回答。建议不等于已选；用户明确授权代选才可代选，已确认的同一交付不重问。

## 等待与续接

提问后，继续完成**不依赖答案且在授权范围内**的整理、证据标注、已确定部分的分析；把依赖该答案的结论、阶段退出、正式验收或 PRD 定稿保持待决。不要循环等待工具、反复催问，也不能替用户选择默认项。若本轮无法获得回复，简短交付已完成部分、待答问题及收到答复后的续接点；这是可恢复的待决状态，不是把任务遗忘或伪装成已通过。

收到用户选项或“其他”文字后，先确认其对应的需求 ID、范围和提问，再按实际含义（包括混合情形）续接；如新答复与已核验事实或另一条变更冲突，指出冲突并核验，不静默覆盖。答复是澄清输入，不自动批准需求变更、扩大授权或覆盖旧 PRD/AC。回到**最早受影响的阶段**更新判断，获准修订时才更新下游文件，复用未受影响的结论，不从头输出整套报告。若用户明确表示暂不回答，普通模式不越过因此无法满足的实施/PRD 门槛；强制范围的普通内容未知仍可带着显式假设推进方案、逐功能点验收与 PRD。唯独未选的 PRD 类型不能由 AI 默认补齐：两种模式均可先完成无关工作，待用户选择或明确授权代选后定稿、导出；这不是恢复产品评估。安全、权限、隐私、合规和真实性边界始终保留。
