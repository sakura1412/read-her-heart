# 统一证据台账

首次把材料用于问题、价值、方案或风险判断时，使用本规则及[台账模板](../templates/evidence-ledger.md)。这是跨阶段的引用层，不是新增阶段或独立评分模型。证据只登记一次，01–08 的判断、验证 Brief、决策记录和 PRD 引用同一编号及版本，不各自改写成多份事实。没有材料时保留缺口，不能为了填表制造证据。

## 最小记录结构

| 字段 | 记录规则 |
| --- | --- |
| **编号** | 项目内稳定 `E-001`；复用已有编号，归并、排序或跨会话不重编、不复用已撤回 ID。不同项目须带项目标识避免碰号。 |
| **来源** | 材料名称/原始标识、版本和可核验位置；注明亲自观察、已读原文或用户转述。同源转发、摘要及二手报道关联同一原始来源组，不凭链接数量当作独立来源。不能访问原文时标明限制，不声称已核验。 |
| **类型** | 访谈 / 数据 / 工单 / 事故 / 系统观察 / 实验 / 业务或技术材料 / 外部公开材料 / 指令等，按实际材料填写。类型只描述获取方式，不代表可靠程度。 |
| **时间** | 事件/观察时间或统计窗口；必要时另记采集/收到时间与适用系统版本。今天收到的旧报表不能写成今天的现状；未知写未知，不补造日期或时效。 |
| **发现与范围** | 一句材料实际显示或声称了什么；用户、场景、环境、样本/口径及适用边界。来源的结论与 AI 的解释分开，不把事件数写成用户数、相关性写成因果。 |
| **强度与依据** | 强 / 中 / 弱 / 未知，并针对所关联的具体判断说明直接性、可核验性、质量及覆盖限制。一个材料支持不同假设的力度不同时分别注明，不能给全局权威分。 |
| **可能偏差/局限** | 如自选样本、幸存者偏差、诱导提问、转述损失、缺分母、埋点错误、版本不匹配、同源重复、未覆盖角色等；无法判断写待核对，不笼统宣称无偏差。 |
| **关联与方向** | 关联需求和具体假设：如 `REQ-001 / H-001：支持`、`H-002：反证`；也可为混合/结论不足或仅背景。支持/反证必须针对一句明确命题，不是材料的永久属性。批量初筛可先关联 REQ 与判断摘要，尚未深入不强造 H/决策。 |
| **状态与版本** | 当前适用 / 待核验 / 当前范围不适用 / 过期 / 已撤回 / 被替代，并注明依据、更新时间及替代 E（如有）。台账有明确修订号；引用写 `E-001@台账v1` 或等效可定位快照。 |

一条 E 对应可独立引用的发现；同一材料包含不同结论时可拆多条 E，但保留同源组，不能当多份独立验证。相同发现的转述可并到原 E 的来源说明；不同转述内容存在冲突时保留差异及来源，不静默归并。AI 推断与尚未执行的计划不是已获得证据：写在假设/缺口中；实际收到的专家意见可以登记为意见材料，但不提升为直接事实。

## 强度不是通过分数

- **强**：对这个具体命题直接、可核验，方法/数据质量足以支撑所述范围，重要局限已交代；不表示可外推到其他角色、时段或价值假设。
- **中**：与命题相关但覆盖、方法或交叉印证有明确限制，支持部分或有条件判断。
- **弱**：间接、单点、未经核验的转述、类比或意见，主要提供线索；单点也可直接证明“发生过一次”，不能因此证明普遍性。
- **未知**：来源、质量或适用范围不足以评定，保留具体缺口，不伪造精度。

分级需说明依据，不按“数据强、访谈弱”、领导级别或反馈声量机械定级。不换算概率、RICE Confidence 或分数；也不按证据条数投票。**E 的强度 ≠ H 的可信度 ≠ 07 判据已满足。** 判断须同时考虑支持、反证、相关性、独立性与时效；一条强反证不能被多份同源弱支持淹没。没有查到证据不等于存在反证；只有已明确的观察范围与检测能力足以支持“没有发生”时，才可据此判断。

市场、竞品和用户研究材料按[专项取证规则](market-user-research.md#市场证据的可信度分级)解释同一强度栏：核对原始方法/样本与客群/地域/时段，保留宣称或实测的区别，不新增平行评分。画像、JTBD归纳及模拟人物是分析产物，不是额外受访者；支持它们的真实材料仍用原E引用。

## 从台账到验证和决策

- **假设 H**：复用 03/04/05/06 或 07 的稳定编号，写明可被支持/反驳的命题和范围；在原分析或 Brief 维护状态与依据，不另建一套同义假设库。
- **07 判据**：引用具体 `E@台账版本 → H@记录版本`，指出现有证据覆盖和剩余缺口；在新增取证前定义支持、不支持、结论不足的观察判据及必要的口径、质量、覆盖条件。数值/样本无依据则待确认，不默认“3 条证据”“强证据一票通过”。见[07](07-validation.md)。
- **实际结果**：收到真实材料后入账或登记修订，保留失败结果和反证，再对照原判据更新 H；规划中的样本只列待采集，不能先生成“已采集”记录。修改判据须保留原版、变更理由及决定来源，不能看到结果后悄悄调到通过。
- **决策 DEC**：在[决策记录](../templates/decision-record.md)中引用 H 与支持/反证 E，说明范围、理由、建议/待决/已批准状态及真实决策人/来源。新编号可用 `DEC-001`，避免与 Delta 的 `D-001` 增量编号混淆；原有编号有明确类型和命名空间时沿用。07 证据判断不替代 08 投入决定，也不改变已有验证预算/期限/轮次约束。
- **PRD 追溯**：保留原需求、指标、FR/AC 链，延伸为 `E → H → DEC → REQ/指标 → FR → AC`。这是可追溯关系而非强制一一对应；必要的支持/反证、未知或不适用说明不能为了画出完整箭头而删掉。指标写实际名称与口径，VAL 是验证计划编号，不能替代指标或 FR/AC，也不能把效果验证结果写成功能验收已通过。PRD 只带决定性摘要与同版引用，不复制整本敏感台账。

当前用户的明确指令可作为“存在此决定”的证据，不是用户价值或风险已接受的证明。强制执行只引用现有指令、方案和风险材料，被跳过假设写未评估，不恢复问题/价值/证据准入门槛，也不因台账缺项阻塞带标注的 PRD；安全、权限、隐私、合规和真实性仍有效。

## 轻量使用、保存与变更

- **简单需求**：把必要 E 与字段压缩在原分析中，可用一两行或短表；有多少材料记多少，不强制独立文件、额外调研或完整假设表。用户明确要台账时用统一表；聊天不再重复同一份材料。
- **批量分诊**：共享一份最小台账/来源索引，分诊行引用 E；缺材料仍记未知，不为全部候选创建七层、H/DEC 或验证 Brief。只有选中项补充影响决策的映射。
- **持久化**：仅在用户授权的项目私有目录保存，可独立用 Markdown 台账；卡片 `links` 引用指定版本，`analysis` 可留 E/H/DEC 索引，不复制可编辑的证据正文。台账负责材料和适用性，JSON 卡片负责需求当前范围/生命周期，不是两个互相覆盖的事实源。未保存只能说本轮已整理，不能声称跨会话已存档；不保存凭证或不必要的个人原文，不把真实业务台账放进公开 Skill 仓库。
- **版本保全**：持久化更新前读取已有台账；实质修订保存新版本或使用项目既有可定位历史，旧 PRD/Brief 引用的快照必须可恢复。新观察给新 E；纠错/撤回保留原 E 和修订记录，不删除历史或重写旧决定。矛盾新材料并列分析，不自动把旧材料标撤回；只有真实纠错、替代或范围失效依据才改变状态。
- **影响回查**：新增反证、撤回、过期或范围/口径改变时，沿 E→H→DEC 查相关 REQ、指标、FR/AC；列出哪些仍有效、哪些待复核及负责人。证据失效不自动推翻全部需求，也不自动覆盖已批准 PRD、卡片或验收规则；按[变更分析](requirement-change.md)只重开受影响判断，修订交付物仍需相应授权。找不到完整映射时标“影响待核验”，不能声称无影响。
