# 事前验尸与反方评审

对复杂或不可逆需求，在 08 投入决策前执行一个可追溯的条件评审环节：**先假设当前方案/验证已经失败，倒推原因；再从不同利益与职责视角挑战当前结论**。它不是泛泛列风险，不新增固定第 11 阶段，也不替代 06 风险判断、07 验证设计或 08 投入决定。

## 触发、对象与位置

- 五维判断为**复杂/战略**（包括已有高影响依据而暂按复杂），或当前范围明确存在不可恢复/难补偿的影响时触发；用户明确要求时也执行。单按钮、少量用户不豁免不可逆影响。
- 仅因信息缺失暂按中等，不自动全套评审；先澄清会改变风险判断的缺口，不能把未知当低。简单需求默认不加此环节；批量分诊只记录触发信号，进入本轮选中项后才执行，不对全池演练。
- 普通路径为 `07 的 Brief/证据充分声明 → 条件评审 → 08`。若从可信上游产物直接进入 08，也检查适用评审是否已完成；同一对象、范围、候选和有效依据未变可引用旧版，不反复重做。
- **本次拟决定验证投入**：假设这次取证失败，检查方法不能区分假设、样本/指标偏差、误把结果当普遍结论、验证本身越界或无法止损等；不要求未知的问题、价值和实施方案提前通过全部门槛。
- **本次拟决定实施投入**：假设所选范围交付或采用失败，检查用户行为、价值兑现、方案机制、依赖、权限/数据、运营承接及回退失效。不得只审技术，也不以“技术可做”消除业务反对意见。
- 已有安全阻断、验证到限停止或明确停止依据立即按原规则处理，不等待评审才停止。若要重新投入、变更候选或改为受控实施，再对相应新范围评审或复用仍适用结论；评审不能复活已用完的预算/轮次。

## 1. 事前验尸：从失败倒推

先固定当前对象/版本、成功目标、范围与拟议投入，写一句**假设情景，不是已发生事实**：“若本范围实施/验证后未达到目标，或产生不可接受损失，最有依据的失败路径是什么？”时间窗口有来源才写具体日期，不虚构事故、概率、损失或工期。

优先少数会改变当前选择的失败路径，不强凑数量。每条说明：

`失败结果 ← 触发条件/因果链 ← 关键假设或脆弱依赖 → 可观察的早期信号 → 预防/最小补证 → 停止、回退或限制范围的条件`

关联已有 E/H、方案/风险编号；区分真实反证、合理失败假设和未知。所谓“最可能”须有定性依据，不能凭想象排出概率榜；无依据则标待核验。回退能力本身也要有依据，不能用“有备份”“可以灰度”掩盖尚未验证的恢复路径。措施写清责任方与关闭点，未知待指定/待确认。

## 2. 反方评审：挑战当前最强结论

选择最可能发现盲点的视角，如受影响的一线用户、业务运营、研发/运维、数据安全或成本承担方；以其任务、约束和损失为出发点，不只更换角色名称。针对当前推荐结论提出最有力的反对理由、替代解释或更便宜的可行候选，并说明**什么事实会推翻当前结论，什么证据又能反驳这条异议**。可以挑战乐观实施，也可以挑战证据不足的过早否决，不预设反方必然正确。

### 独立性与工具边界

宿主有可用、允许的子代理且材料可在该范围共享时，优先让一个未参与原论证的独立上下文执行反方评审。只提供最小材料包：当前决策问题、范围/候选版本、成功判据、关键 E/H（含反证与局限）、依赖/约束和待质疑结论；不提供“帮我证明它合理”的引导或要求达成一致。让评审者先独立提出异议，再由主分析回应。无需复制整段对话、凭证或无关业务数据，不为此创建用户的新任务、联系外部评审人或执行系统操作。

没有独立代理、能力不可用或材料不允许共享时，仍以另一视角单独复核，显著标 **“单模型反方复核，非独立评审”**，不能声称另一位专家已审核。确未执行则写待评审，不伪造意见或签字。记录实际评审方式/视角/输入版本及限制；AI 多视角或多个代理都不等于真人安全/法务审核、独立实证或发布批准。需专业确认的事项保留真实确认责任，工具不可用本身不冻结其余分析或强制 PRD。

## 3. 对异议作出处理，而非只追加风险清单

同一份[评审记录](../templates/premortem-review.md)用稳定 `REV-001` 与发现编号（如 `REV-001-F01`）承接两步；重复发现只保留一个条目并关联来源。每条重要异议都保留：

- 所挑战的结论、依据 E/H 与适用范围；若只是推测，明确为假设。
- **采纳 / 部分采纳 / 不采纳 / 待核验**，以及依据和具体处理。不能用“已考虑”“风险可控”当作关闭理由；不采纳也须解释适用边界或反驳证据，保留原异议。
- 影响哪些候选、需求、指标、风险或 FR/AC，需返回哪个判断、由谁在什么条件下关闭。

问题/价值或替代解释的发现回填 03/04；候选缺陷与替代方案回填 05；权限、恢复和依赖问题回填 06；关键证据/方法缺口交 07 补最小验证设计。新的真实材料按[证据台账](evidence-ledger.md)入账，评审中的想象失败或模型意见不能充当事故证据，也不能因多位 AI 一致就变成独立支持证据。

## 4. 收尾、复用与决定边界

默认一轮事前验尸与反方评审，加上对实际修改的针对性复核；无新证据/范围变化时不自动反复辩论或继续招募评审。仍有分歧就保留异议、条件与需谁决定，不以虚构共识结束。评审内容收尾不等于风险已消除或方案已获批准。

- **可以交 08**：评审已执行，重要发现已明确处理方向和残余缺口。08 判断本次验证/实施是否值得投入；评审不代替决定，也不自动执行措施。
- **实施关键缺口未闭**：对应范围不能被写成已满足实施门槛；可返回相关阶段，或仅把安全、有限的补证方案交 08 考虑。不能要求先消除所有产品未知才讨论验证成本。
- **验证本身不安全、不能产生可判读证据或已越限**：调整/停止该方法，保持原累计限制，不因换反方或新假设编号而重开额度。
- **明确不可接受的安全、权限、隐私或合规冲突**：调整方案或阻断受影响范围，不能以风险接受或评审多数票豁免；未受影响的安全部分仍可继续。

决策 DEC 引用 `REV@版本` 与关键发现及处置；07 Brief 引用受影响假设/判据，PRD 只纳入实际采纳的控制与必要残余风险，不复制整段争论。已提出的措施不自动成为已批准规则或已执行 AC。复杂度、候选、证据适用性、数据权限、依赖或回退前提发生实质变化时，按[变更分析](requirement-change.md)只重开受影响发现；从早期验证转入实施须核对评审对象，不能拿“验证方案审过”代替实施评审。

## 强制执行与轻量交付

强制项不经过 08：高复杂/不可逆时把本环节的**方案失败、安全、依赖和回退挑战**嵌入 06 轻量风险知情单，先质疑方案如何失败，再以不同视角复核控制，记录重要异议和处置；不重新论证“值不值得做”，不恢复 03/04/07/08。缺普通证据、独立评审者或风险确认人可如实标注后继续 PRD；不可接受底线风险仍调整/阻断受影响范围，不能把材料不全当作已获安全许可。

默认聊天只呈现关键失败路径、最有力异议、处理结果及其对下一步的影响；不再重述整套阶段报告。独立文件仅按用户交付/保存范围生成；持久化仍用已授权项目私有目录，需求卡 `links` 引用评审版本即可，不新增必填 schema，不把业务评审写进公开 Skill 仓库。
