# 五维复杂度判断

在最小需求整理后、深入需求分析或强制方案设计前，按需求 ID 和本次范围判断复杂度，再选择分析深度与后续 PRD 详略。分类说明“是什么需求”，复杂度说明“需要分析和记录多深”；两者不能替代问题、价值或投入判断。

```text
复杂度 = 业务影响 × 系统影响 × 用户影响 × 数据风险 × 不可逆性
```

未指定评分量表与分级阈值时，将“×”作为五维相互放大的判断框架，不输出伪精确乘积。默认每维记录“低 / 中 / 高 / 未知”及关键依据，再按下文定性路由，不得将等级默认映射为数字。只有用户明确数值口径、各维取值依据与复杂度阈值后，才按该公式计算；数值结果不能抵消安全约束。

## 五个维度

结合实际范围和证据使用以下分级锚点，不按页面数量、需求字数、领导级别或 AI/Redis 等名称直接定级。

| 维度 | 低 | 中 | 高 |
| --- | --- | --- | --- |
| 业务影响 | 局部非核心流程，不改变交易、收费或履约规则 | 单条业务规则、部门流程或协作方式改变 | 核心交易、定价权益、履约责任、经营模式或战略方向改变 |
| 系统影响 | 单模块局部展示/配置，无接口、状态或共享能力变化 | 单系统多模块、接口或状态流转变化，依赖可界定 | 跨系统链路、共享基础能力、多租户边界或大规模迁移 |
| 用户影响 | 有限角色的局部任务，使用习惯基本不变 | 多角色协作或操作习惯明显改变，需要迁移或培训 | 大范围核心任务变化，或即使人数少也会严重影响其关键任务、权益或可访问性 |
| 数据风险 | 不涉及敏感数据、权限边界或破坏性数据操作 | 常规业务数据增改，影响可追踪且有明确恢复路径 | 敏感数据、跨租户/越权暴露、关键数据完整性或永久丢失风险 |
| 不可逆性 | 可快速回滚，数据及用户影响可恢复 | 需补偿、人工恢复或用户配合才能纠正 | 重大影响难以恢复或补偿，如不可恢复删除、不可撤回的大范围操作、长期约束承诺 |

“业务影响高”不是“收益高”；人数少不等于用户影响低；只有一个按钮也可能触发跨系统或不可逆操作。没有证据确认边界时写“未知”，不能把未实查当成无系统影响，也不能编造人数、收益或研发工作量。

## 综合定级与分析路由

- **简单**：五维均有依据为低，且没有额外的联动放大。普通模式紧凑完成七层判断，不使用方法框架；方案聚焦主路径、适用异常、权限与验收。
- **中等复杂**：存在中等影响，但无高影响维度或显著级联风险。普通模式围绕主要不确定性分析，最多选 1～2 个方法；重点补齐相关角色、规则、依赖和替代方案。
- **复杂/战略**：任一维度有高影响依据，或多个中等维度相互作用导致核心链路影响、故障传播或恢复范围显著扩大。必须说明具体联动关系，不能只数“中”的数量。按受影响的流程/系统/角色拆解，深入数据边界、迁移、回退和验证设计；允许多个各有用途的方法，但不强制堆叠。
- **存在未知**：标明“复杂度待确认”，同时给出临时分析档位和影响定级的缺口。已有高影响证据则按复杂处理；否则先用中等档位做最小澄清，不把未知当低，也不自动展开全部框架。只补会改变档位或分析重点的信息，已明确的部分可以继续；获得新证据后再定级。

低影响项不能抵消高风险项；也不能只凭最大项省略其余四维。上述是未采用数值量表时的定性路由，不声称算出了数学乘积。五维判断本身、九阶段、七层决策和价值判断链不计入方法数量；RICE 仍遵守其独立的数据与计算限制。

## 使用与更新

- 先记录五维画像和档位，再按该档位展开分析；信息不足时可以先澄清或在授权范围实查，不要求为了定级先做一遍完整需求评估。
- 02 实查、新证据、范围变化或候选方案变化影响某维度时，只更新相关维度、联动关系、分析深度与 PRD 详略，复用其他有效结论。原需求与替代候选的影响变化须注明，不能仅因换了方案就改写先前事实。
- 同批需求分别判断；确有共享依赖或风险传播时额外说明联动影响，不把所有需求一律升为复杂。
- 强制执行也先做简短五维判断，用于方案细化、依赖与安全约束的覆盖深度，以及 PRD 层级选择；不重新评估问题/价值/证据/优先级，不因复杂度未知停止 PRD。未知项进入方案和 PRD，安全、权限、隐私和合规边界照常保留。
- 进入 09 后复用该复杂度选择 PRD 详略：简单用简版，中等或临时中等用标准版，复杂/战略或已知高影响用完整版；详见 [PRD 分级](09-prd-generation.md#按复杂度选择-prd-详略)。复杂度更新影响文档层级时，只补变动带来的内容。
- 默认只呈现一行“需求 ID：五维等级 → 复杂度（必要时暂定）→ 分析重点/方法”；关键依据和缺口并入现有记录，不额外输出重复长报告。后续追问仅在档位或范围变化时更新，不每轮重新定级。
