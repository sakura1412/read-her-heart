| 原子需求 | 规范化的问题/目标 | 主类型 | 关联类型 | 来源/驱动标签 | 用户提出的候选方案 | 分类理由与置信度 | 由分类触发的分析重点 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  | A/B/C/D/E/H/I/J/K/待分类 | 无/类型 | F 领导指定/G 用户强诉求/监管强制/合同承诺/数据或事故驱动/内部效率/市场或竞品驱动 | 无/具体方案 | 理由；高/中/低 | 重点问题、最低证据、需避免的误判 |

## 方法选择门槛

七层决策链和价值判断链是固定决策记录，不计入方法数量。先判断复杂度，再决定是否加载后续方法模板。

| 复杂度 | 常见特征 | 方法数量限制 | 输出要求 |
| --- | --- | --- | --- |
| 简单 | 单一角色/任务或局部流程；问题清楚；低成本、可逆、低风险；不涉及跨系统或合规 | 不使用框架 | 简洁回答七层问题，不展示任何方法模板 |
| 中等复杂 | 多步骤或多角色；根因、范围、方案或证据存在明显不确定性；中等投入或风险 | 最多 1～2 个 | 说明每个方法减少哪项关键不确定性 |
| 复杂/战略 | 跨部门/系统、多角色、高投入、不可逆、敏感数据、迁移、安全合规或战略影响 | 可以组合多个 | 每个方法服务于不同层级，不叠加功能重复的方法 |

复杂度按最高风险和最大影响判断，不按文档长度或期望输出长度判断。

## 价值判断链（固定顺序）

第一层问题至少“部分成立”后，对每个可独立决策的需求分别填写一行。多个需求不得混在同一行。

| 需求 | 价值假设 | 影响指标 | 当前基线 | 预期变化 | 证据来源 | 可信度 |
| --- | --- | --- | --- | --- | --- | --- |
| 具体、可独立决策的需求 | 如果…将使某类用户/业务…因为… | 指标名称、口径、时间窗口 | 当前值、周期、范围；未知则写待测 | 方向、幅度/区间、观察周期；无依据则写定性假设 | 来源类型、具体材料、时间与覆盖范围 | 高/中/低＋理由 |

填写规则：

- **价值假设**是待验证陈述，不得写成已经发生的事实。
- **影响指标**必须能够验证价值是否发生；无法量化时也要给出可观察的行为或结果信号。
- **当前基线**缺失时写“未知/待测”，并说明如何获得，不能使用猜测值。
- **预期变化**没有历史数据、实验或可靠类比支持时，不写精确百分比，只写方向或区间假设并降低可信度。
- **证据来源**应能追溯到数据报表、行为数据、实验、用户研究、工单、业务记录、系统观察、技术材料、专家判断或纯假设，并标明时间和覆盖范围。
- **可信度高**通常需要直接、相关、近期且覆盖范围足够的证据；部分数据或多方一致但覆盖有限为中；单点反馈、间接类比、专家判断、纯假设或缺少基线为低。
- 第一层问题不成立时整条链标为“不适用”；问题待验证时可以保留初步假设，但其他字段必须如实暴露缺口。

## 七层决策链（必须按顺序）

投入程度和行动出口只能在完成前六层后填写。不得先给结论再倒推理由；前一层不成立时，将后续不适用项标为“不适用”并说明停止点，不虚构证据。

| 层级 | 必答问题 | 支持证据 | 反证/不利信号 | 关键假设 | 阶段判断 | 置信度 | 未确认项与下一步 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 是不是真的有问题？ |  |  |  | 成立/部分成立/不成立/待验证 | 高/中/低 |  |
| 2 | 问题是否值得解决？ |  |  |  | 成立/部分成立/不成立/待验证/不适用 | 高/中/低 |  |
| 3 | 用户提出的方案是不是正确方案？ |  |  |  | 成立/部分成立/不成立/待验证/不适用 | 高/中/低 |  |
| 4 | 有没有更便宜的替代方案？ |  |  |  | 有/没有/待验证/不适用 | 高/中/低 |  |
| 5 | 当前证据够不够？ |  |  |  | 充分/部分充分/不足 | 高/中/低 |  |
| 6 | 风险是否可接受？ |  |  |  | 可接受/有条件可接受/不可接受/待评估/不适用 | 高/中/低 |  |
| 7 | 最后决定投入程度 | 汇总前六层；剩余不确定性、做错损失、可逆性、验证成本与实施成本 |  |  | 不投入/验证投入/实施投入（受控范围/分阶段/完整） | 高/中/低 | 映射到不做/先验证/直接做；写明升级、停止、重开或回退条件 |

### 各层检查提示

- **问题真实性**：用户、场景、频率、严重度、当前行为、问题造成的损失和反例。
- **解决价值**：用户价值、业务价值、战略一致性、影响范围、机会成本和不解决的后果。
- **方案正确性**：是否命中根因、是否适配流程、预期结果、操作负担和副作用。
- **替代方案**：不改、配置、流程优化、培训/引导、人工处理、复用、缩小范围、采购和新建。
- **证据充分性**：关键结论是否由数据、用户研究、系统事实、业务材料或技术证据支持；哪些仍是假设。
- **风险可接受性**：产品、技术、数据、隐私安全、法律合规、运营、采用、迁移、可逆性和维护风险。
- **投入程度**：只能汇总前六层后判断；说明剩余不确定性是否会改变决策、验证或实施是否比做错更划算，并明确成功、失败、升级、停止、重开和回退条件。

## 七层门槛与投入决策

```text
需求
 ↓
① 是不是真的有问题？
 ↓
② 问题是否值得解决？
 ↓
③ 用户提出的方案是不是正确方案？
 ↓
④ 有没有更便宜的替代方案？
 ↓
⑤ 当前证据够不够？
 ↓
⑥ 风险是否可接受？
 ↓
⑦ 最后决定投入程度
 ├─ 不投入 ─────────→ 不做（含暂停）
 ├─ 验证投入 ───────→ 先验证
 └─ 实施投入 ───────→ 直接做（受控范围 / 分阶段 / 完整投入）
```

### 最终行动卡

| 七层实际决策路径 | 停止或分支门槛 | 投入程度 | 行动出口 | 核心依据 | 置信度 | 必须附带的条件 |
| --- | --- | --- | --- | --- | --- | --- |
| ①问题 → ②价值 → ③方案 → ④替代 → ⑤证据 → ⑥风险 → ⑦投入 | 哪一层决定或限制投入 | 不投入/验证投入/实施投入 | 不做/先验证/直接做 | 证据、反证和关键假设 | 高/中/低 | 见下方规则 |

- **实施投入 → 直接做**：写明受控范围、分阶段或完整投入的选择依据，以及验收指标、停止条件和回退条件。直接做不等于默认全量开发。
- **验证投入 → 先验证**：写明待验证假设、方法、成本/周期（未知则标记未知）、成功阈值、失败条件；明确验证成功进入“实施投入”，失败进入“不投入”或重新设计。不得凭空估算验证成本；成本未知且会影响选择时，先取得研发、运营或研究估算。
- **不投入 → 不做（含暂停）**：写明失败的前置门槛，以及什么新证据或条件允许重开。不得用没有重开条件的“以后再说”代替结论。
- **延后**不是第四种判断结论。只有已经判定“直接做”后，才可因资源、依赖或窗口把它作为排期状态，并给出重新排期条件。

## RICE 定性记录（默认不计算）

| 候选需求 | Reach | Impact | Confidence | Effort | 判断依据 |
| --- | --- | --- | --- | --- | --- |
|  | 未知/低/中高/极高 | 未知/低/中高/极高 | 未知/低/中高/极高 | 待研发确认 | 写明已有证据和未知项 |

默认规则：

- **Reach** 只能填写“未知 / 低 / 中高 / 极高”。
- **Impact** 只能填写“未知 / 低 / 中高 / 极高”。
- **Confidence** 只能填写“未知 / 低 / 中高 / 极高”。
- **Effort** 默认填写“待研发确认”；没有研发提供的估算时，不自行推测人日、人周或人月。
- 不给等级设置默认数字，不把“低 / 中高 / 极高”自动换算为系数，也不输出伪精确的 RICE 分数。
- 定性记录只用于同一语境下比较多个候选需求，并且要说明每个等级的判断依据和未知项。

### 数值计算的启用条件

只有用户主动提供以下完整数据时，才可以考虑计算 `(Reach × Impact × Confidence) / Effort`：

1. Reach 的数值、统计时间窗口和用户/事件口径。
2. Impact 的数值定义或用户明确提供的换算标准。
3. Confidence 的数值或用户明确提供的换算标准。
4. Effort 的研发估算及统一单位。

任一项缺失、时间窗口不同、统计对象不可比或投入单位不统一时，不计算，只保留定性记录并标明缺口。
