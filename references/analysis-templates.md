# 需求分析模板

只使用与当前问题相关的模板，不要为了形式完整而全部填写。系统实查后的可行性判断还应结合 [系统实查指南](system-inspection.md) 中的可行性分层。

## 方法选择门槛

七层决策链是固定决策顺序，不计入方法数量。先判断复杂度，再决定是否加载后续方法模板。

| 复杂度 | 常见特征 | 方法数量限制 | 输出要求 |
| --- | --- | --- | --- |
| 简单 | 单一角色/任务或局部流程；问题清楚；低成本、可逆、低风险；不涉及跨系统或合规 | 不使用框架 | 简洁回答七层问题，不展示任何方法模板 |
| 中等复杂 | 多步骤或多角色；根因、范围、方案或证据存在明显不确定性；中等投入或风险 | 最多 1～2 个 | 说明每个方法减少哪项关键不确定性 |
| 复杂/战略 | 跨部门/系统、多角色、高投入、不可逆、敏感数据、迁移、安全合规或战略影响 | 可以组合多个 | 每个方法服务于不同层级，不叠加功能重复的方法 |

复杂度按最高风险和最大影响判断，不按文档长度或期望输出长度判断。

## 七层决策链（必须按顺序）

最终投入建议只能在完成前六层后填写。前一层不成立时，将后续不适用项标为“不适用”并说明原因，不虚构证据。

| 层级 | 必答问题 | 支持证据 | 反证/不利信号 | 关键假设 | 阶段判断 | 置信度 | 未确认项与下一步 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 是不是真的有问题？ |  |  |  | 成立/部分成立/不成立/待验证 | 高/中/低 |  |
| 2 | 问题是否值得解决？ |  |  |  | 成立/部分成立/不成立/待验证/不适用 | 高/中/低 |  |
| 3 | 用户提出的方案是不是正确方案？ |  |  |  | 成立/部分成立/不成立/待验证/不适用 | 高/中/低 |  |
| 4 | 有没有更便宜的替代方案？ |  |  |  | 有/没有/待验证/不适用 | 高/中/低 |  |
| 5 | 当前证据够不够？ |  |  |  | 充分/部分充分/不足 | 高/中/低 |  |

### 各层检查提示

- **问题真实性**：用户、场景、频率、严重度、当前行为、问题造成的损失和反例。
- **解决价值**：用户价值、业务价值、战略一致性、影响范围、机会成本和不解决的后果。
- **方案正确性**：是否命中根因、是否适配流程、预期结果、操作负担和副作用。
- **替代方案**：不改、配置、流程优化、培训/引导、人工处理、复用、缩小范围、采购和新建。
- **证据充分性**：关键结论是否由数据、用户研究、系统事实、业务材料或技术证据支持；哪些仍是假设。
- **风险可接受性**：产品、技术、数据、隐私安全、法律合规、运营、采用、迁移、可逆性和维护风险。
- **投入程度**：明确为何选择该级别，以及升级投入、停止和回退的可观察条件。

## RICE 口径

| 维度 | 建议口径 |
| --- | --- |
| Reach | 固定时间窗内被影响的目标用户或事件数 |
| Impact | 对核心目标的单用户影响，使用约定的相对分级 |
| Confidence | 证据可信度；高=数据/实验，中=多方一致反馈，低=假设 |
| Effort | 跨职能总投入，如人周或人月 |

RICE 只用于同一口径下的相对比较。不要将不同时间窗、不同用户群或不同 Effort 单位混在同一排序中。
